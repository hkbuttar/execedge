# Backend (FastAPI)

Serves backtest, calibration, and training results as JSON. Every route
is a thin wrapper over `backend/services.py`, which itself only composes
already-tested logic from `backtest/`, `algos/`, `venues/`, and `rl/` —
this layer adds no new statistics or execution mechanics of its own, and
reuses the exact same functions the CLIs do (`backtest.scenarios.build_algorithm_scenarios`,
`backtest.experiment.run_bootstrap_experiment`, `venues.cross_venue_validation.compare_rankings_across_venues`,
`rl.diagnostics.diagnose_training_run`, etc.).

## What's deliberately NOT exposed here

Long-running/blocking operations — recording a live book
(`lob.run_reconstruction`, holds a websocket open indefinitely) and
training an RL policy (`rl.train`, can take arbitrarily long) — aren't
wrapped as endpoints. An HTTP request that blocks for however long a
websocket connection or a training run takes is the wrong shape for a
request/response API; those stay CLI-only, as documented in `lob/README.md`
and `rl/README.md`. This backend serves/queries results from data you've
already recorded or trained, plus fast synchronous computations
(a single backtest, a bootstrap experiment over already-recorded windows,
a calibration comparison, a cross-venue ranking check).

## Routes

| Route | Wraps |
|---|---|
| `GET /health` | — |
| `POST /backtest` | `backtest.simulator.OrderSlicingSimulator` — one algorithm, one parent order |
| `POST /experiment` | `backtest.scenarios` + `backtest.experiment` — regime-stratified bootstrap comparison |
| `POST /calibration/compare` | `algos.impact_calibration.compare_calibrations` |
| `GET /venues/fees` | `venues.fees.VENUE_FEE_SCHEDULES` |
| `POST /venues/cross-validate` | `venues.cross_venue_validation` — same logic as `venues.run_cross_venue_validation`, one venue's results per book history given |
| `POST /rl/diagnostics` | `rl.diagnostics.diagnose_training_run` |
| `GET /results` | raw `RESULTS.md` content |

Bad input (missing file, missing required calibration args, too little
real data to bootstrap) returns HTTP 400 with the same error message the
underlying CLI would print — nothing is silently swallowed.

## Usage

```
uvicorn backend.main:app --reload
```

Then, e.g.:

```bash
curl -X POST http://localhost:8000/backtest -H 'Content-Type: application/json' -d '{
    "book_history_path": "lob/raw/binance_book_snapshots.jsonl",
    "side": "buy", "quantity": 1.0, "algorithm": "twap", "n_slices": 5,
    "duration_seconds": 300,
    "temporary_impact_coef": 0.0, "permanent_impact_coef": 0.0
}'

curl http://localhost:8000/venues/fees
curl http://localhost:8000/results
```

Interactive docs (Swagger UI) at `/docs` once running, auto-generated by
FastAPI from `backend/schemas.py`'s Pydantic models.

## Tests

`tests/test_backend.py` — 14 tests using FastAPI's `TestClient` (no
server process needed) against synthetic book histories, volume/regime
CSVs, and a rewards CSV: every route's happy path, plus the 400 error
paths (missing file, `ac` algorithm without required calibration args,
too few windows to bootstrap, fewer than 2 venues with usable
cross-validation results). Also smoke-tested manually against this
project's own real recorded Binance data and `RESULTS.md`'s real
numbers — the API's `/backtest`, `/experiment`, `/calibration/compare`,
and `/rl/diagnostics` responses matched `RESULTS.md` exactly, since both
call the identical underlying functions.
